任务详情抽屉 · 两方案对照（T-20261015-025759）

两栏都是可交互原型，共用同一批写死样例（各渲染点带 <!-- SAMPLE DATA · 实现卡需接 GET /api/v1/tasks/:ref/reports --> ）。点任意卡片打开抽屉，再按各栏自己的控件试。默认两栏都是现在的抽屉形态，差异只在打开之后。
注意：两栏各约 750px 宽，窄于原型自身的 760px 断点，因此框内抽屉本来就会占满宽度 —— 想看 520px 抽屉与满屏形态的差别，请单独以全宽打开 index-detail-full.html（方案一）与 index-detail-tabs.html（方案二）。 下面的两张截图 screenshots/d1-full-on.png、 screenshots/d2-tabs-reports.png 是 1512px 下的原生尺寸读数。

方案一

「开启详情」满屏开关

抽屉头右侧多一个开关。关 = 现状（520px 抽屉，report 家族不出现）；开 = 抽屉变成覆盖整个可视区域的满屏层， 既有 7 区之后接 Reports / Conclusion / Acceptance / Leftovers，纵向堆叠。 开关状态记在浏览器 localStorage["meerkat.detail.fullDetails"]， 默认关，换任务 / 刷新 / 重开标签都按它展示。

方案二

抽屉内按信息角色重排（Tab）

抽屉体顶部加一条 Tab 条，按「信息角色」分四轴：Details（卡是什么，= 现状 7 区）/ Reports（做完了什么）/ Acceptance（凭什么算完成）/ Leftovers（还差什么）。默认停 Details，因此默认面与现状等价； 键盘 ← / → 循环、Home / End 首尾。
